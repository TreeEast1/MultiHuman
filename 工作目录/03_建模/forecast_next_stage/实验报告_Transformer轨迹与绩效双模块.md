# 实验报告：趋势预测的双模块——Transformer 窗级轨迹与 Ridge 绩效 S

**结论分两句。** 软件里「实线已观察 / 虚线未来」画的是人因指标的窗级轨迹，用 **池化 Transformer 直接预报、再按最后观测点锚定**。右侧「人员状态 / 预测绩效 S」仍走正式口径：已观察定额 27 维 → 标准化 Ridge → 冻结浅树 XGB 得 NASA，再按步骤 0.70 / 负荷反向 0.30 合成 S。官方验证为未见过的 **5 人、17 条任务**（被试 2、7、12、16、23），该组 **S 的 R² = 0.965，MAE = 0.020**。

S 一场任务只有一个数，不能画成随时间起伏的曲线。虚线交叉阈值的时刻也没有验证过，界面上只作示意。

示范样本：`subject_02_task_5_6`。真值 S = 0.662，Ridge S = 0.679。心率虚线从最后观测点连续出发，后半段标准差约 2.2 bpm（真值约 2.8 bpm）。

---

## 1. 要解决的软件问题

徐安琪老师这边的「趋势预测与预警」需要同时满足两件事：

1. **图上要看得出状态在变。** 均值回归、Holt、残差衰减在窗级误差上往往更好，但虚线很快走平，看起来不像预报。
2. **报告里要有完整的时序深度学习接法**，而不是只写一句「对 27 个数做了岭回归」。

这两件事不能靠同一个头硬扛。把 Transformer 的窗级预报拼回 264 维再进 XGB，官方折 NASA R² 会到 **−0.489**（假后半段把 std、slope 污染掉）。共享编码器再分一个 27 维任务头，S 的 R² 只有 0.884，而且预测会塌成少数几个重复水平。

因此做成 **双模块**：

| 模块 | 输出 | 方法 | 用途 |
|---|---|---|---|
| 轨迹 | 后半段 8 条窗级曲线 | 池化 Transformer + 末值锚定 | 主图与缩略图的虚线 |
| 绩效 | 一个 S | V8 Ridge 27 → XGB | 预警、人员状态 |

---

## 2. 数据与切分

与正式 S 口径同一套预处理。窗长 30 秒、步长 5 秒。轨迹头用 8 条可画的窗口指标：心率均值 / 心率波动 / 瞳孔 / AOI 覆盖 / 操作密度 / 操作次数 / 额区 θ/α / 眨眼频率。绩效头仍用折内 MI 定额 27 维（眼 6 + 脑电 5 + 心率 4 + 行为 12）。

| 项 | 设置 |
|---|---|
| 被试 | 26 人 |
| 可切半的任务 | 82 条 |
| 已观察 / 未来 | 各 50% 窗口 |
| 划分 | 按被试 GroupKFold，5 折 |
| 验证组 | 被试 2、7、12、16、23，17 条 |

训练时验证组的人完全不出现。新人必须先留下本场已观察段，不能零观测只靠其他人的均值。

绩效

\[
S = 0.70 \times \text{真实步骤} + 0.30 \times (1 - \widehat{\mathrm{NASA}}/10).
\]

步骤用真值，不预报。NASA 由冻结 XGB 给出。没有窗级 S。

---

## 3. Transformer 怎么接到轨迹上

实现是 numpy 自动微分（本机 PyTorch 拉取不稳定），容量刻意做小，便于复现和写进报告。

### 3.1 池化 Transformer（采用）

1. 最近 24 窗线性嵌入到 16 维。
2. 单头自注意力，残差 + ReLU 前馈。
3. 时间维平均，得到一个上下文向量。
4. 用正弦位置编码生成 32 个查询，逐步解码后半段，再插值到真实长度。
5. **训练**：直接拟合后半段（`direct`），不是拟合残差。
6. **推理锚定**：\(\hat y \leftarrow \hat y - \hat y_0 + y_{\mathrm{last}}\)，第一点贴住「现在」，形状保留。

### 3.2 编码器–解码器 Transformer（对照）

编码同上；解码每一步对编码序列做交叉注意力。这是更标准的 encoder–decoder。在本批数据上，它几乎学会了「把最后一点水平延长」。

### 3.3 还试过的目标与损失

| 名称 | 训练目标 / 损失 | 意图 |
|---|---|---|
| direct | 后半段本身 | 保留形状 |
| resid | 相对已观察均值回归的残差 | 提高窗级 R² |
| delta | 相对最后一点的增量 | 从末值连续出发 |
| cycle | 相对末段周期复制的残差 | 加上准周期先验 |
| wave | 真值与末段周期的混合，再减末值 | 强迫解码器出波动 |
| diff | delta + 一阶差分 MSE + 方差对齐 | 防止塌成水平线 |

末段周期：用已观察心率的自相关估计周期（约 6–18 窗），把最后一整段循环铺到未来。这是结构化基线，不是深度学习。

## 4. 消融结果

### 4.1 五折窗级（8 条曲线一起评）

| 算法 | 后半段 R² | 心率 R² | 官方折窗级 R² |
|---|---:|---:|---:|
| 均值回归 | +0.267 | +0.863 | +0.040 |
| 池化 Transformer 残差 | +0.221 | +0.825 | +0.008 |
| 池化 Transformer 直接 | +0.168 | +0.747 | −0.022 |
| 编解码器 + 末值残差 | −0.118 | +0.791 | −0.158 |
| 重复最后一点 | −0.231 | +0.825 | −0.165 |
| 池化 + 末值残差 | −0.260 | +0.772 | −0.207 |
| 末段周期复制 | −0.261 | +0.804 | −0.468 |
| 池化直接再锚定 | −0.275 | +0.751 | −0.288 |

均值回归、残差接法误差更小，但虚线走平。直接预报形状最好看，电平会跳；锚定之后连续，但 R² 变差——相位和振幅对不齐时，多出来的波动会被算成误差。**窗级 R² 不作为对外成绩。**

### 4.2 官方折：虚线会不会动

只看每条任务内部、心率预报的标准差。跨任务拼起来再算「动态比」会把不同人的基础心率差算进去，水平线也会显得「很动态」。

| 方法 | 心率预报中位标准差 (bpm) |
|---|---:|
| 重复最后一点 | 0.00 |
| 编解码器，仅 MSE | 0.04 |
| 编解码器 + 差分 / 方差损失 | 0.04 |
| 编解码器 + 周期形状混合 | 0.07 |
| 均值回归 | 0.27 |
| 末段周期复制 | 0.65 |
| **池化 Transformer 锚定** | **1.86** |

小型编解码器即使用差分损失和周期混合目标，也仍塌在末值附近。会动的深度学习虚线来自 **direct + 锚定**。LSTM 教师强制 + 滚动预报在更早的对照里后半段 R² 为负（−0.17），没有采用。

### 4.3 接到 S

| 路径 | 官方折 S R² | NASA R² |
|---|---:|---:|
| **V8 Ridge 27 → XGB** | **0.965** | **+0.650** |
| 只用已观察 27 | 0.908 | +0.071 |
| 双头 Transformer 出 27 维 | 0.884 | −0.166 |
| 窗级预报拼回 264 再 XGB | 0.772 | −0.489 |
| 真值 264（oracle） | 0.971 | +0.528 |

预警只报 Ridge 这一路的 S。不把 NASA R² 0.26（全样本、另一套汇总）写进对外摘要。

## 6. 不写进结论的话

- 不说「Transformer 预测了 S」，S 是 Ridge 27 给的。
- 不说窗级心率 R² 是正式指标。
- 不把虚线与真值相位不一致的峰谷解释成已经预报准了下一次波动。
- 不把带宽或与阈值的交点写成经过验证的超限时刻。
- 不把编解码器 + 差分损失写成已经解决塌缩；消融说明它在本容量下没有解决。
