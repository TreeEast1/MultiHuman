# v16：编解码器消融 + 末值锚定 Transformer 轨迹

## 选定

| 项 | 落地 |
|---|---|
| 窗级轨迹（界面虚线） | **池化 Transformer 直接预报 + 末值锚定**（`pool_anchor`） |
| 示范样本 | `subject_02_task_5_6`（官方验证折，被试 2） |
| 该条 S | 真值 0.662，Ridge 0.679 |
| 正式 S / 预警 | V8：已观察 27 → 标准化 Ridge(α=10) → 冻结 XGB → 公式 S |
| 官方 17 条 S | R² **0.965**，MAE **0.020** |

`pool_anchor` 先按直接目标训出后半段形状，再把整条预报平移，使第一点等于最后观测值。虚线从「现在」连续出发，并保留状态波动。图：`figures/fig_tf_v16.png`、`figures/fig_tf_v16_demo.png`、`figures/fig_ui_trend_warning.png`。

## 为什么还要继续试 Transformer

均值回归、Holt、残差衰减在窗级 R² 上更好看，但虚线很快走平，软件里不像「趋势预测」。直接预报的 Transformer 形状最像状态曲线，但电平会跳。末值锚定保留形状、去掉跳变。

S 不能画成时间序列：一场任务只有一个公式 S。窗级虚线是 8 / 27 路人因，不是 S。

## 架构

**池化 Transformer**（轨迹头，实际采用）

1. 取最近 24 窗，线性嵌入到 16 维。
2. 单头自注意力 + 两层前馈，时间维平均池化得到上下文。
3. 用 32 个正弦位置编码查询，逐步解码后半段（再插值到真实长度）。
4. 训练目标：后半段本身（`direct`）。
5. 推理：`ŷ ← ŷ − ŷ₀ + y_last`。

**编码器–解码器 Transformer**（对照）

编码同上，解码每一步对编码序列做交叉注意力。按理更「像 Transformer」，但在本数据、本容量下，MSE 会把输出训成近似「重复最后一点」。

## 官方折：波动还在不在

只看官方 17 条、心率预报的**任务内**标准差（池化后的动态比会把「不同人的水平差」算进去，不能用来判断虚线会不会动）。

| 方法 | 心率预报中位标准差 (bpm) | 与末值跳变中位 |
|---|---:|---:|
| persist_last | 0.00 | 0.00 |
| encdec_mse（仅 MSE） | 0.04 | 0.42 |
| encdec_diff（+ 一阶差分 / 方差损失） | 0.04 | 0.42 |
| encdec_wave（+ 真值与末段周期混合） | 0.07 | 0.57 |
| mean_revert | 0.27 | 0.13 |
| last_cycle（末段周期复制） | 0.65 | 1.00 |
| **pool_anchor** | **1.86** | **0.00** |

差分损失、周期形状损失都没把小容量编解码器从水平线里拉出来。会动的深度学习虚线来自 **direct + 锚定**。

窗级 R² 仍是均值回归 / 残差更高；它们走平。`pool_anchor` 的 R² 为负，是因为形状对了、相位和电平仍会偏。**不以心率 R² 当正式成绩，也不把虚线交叉时刻写成「何时超限」的验证结论。**
