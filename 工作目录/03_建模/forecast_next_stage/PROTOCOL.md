# 下一阶段人因指标预报 → 定额 XGB 合成 S：实验协议

本文是验收用的方法说明。数字以 `reports/` 下各版本 JSON / Markdown 为准。

## 1. 要解决的问题

现有正式口径（`s_score_from_nasa84`）是：

```
整次任务的 264 维人因指标
    → 折内互信息定额 27 维（眼动 6 / 脑电 5 / 心率 4 / 行为 12）
    → 浅树 XGB 预测 NASA-TLX
    → S = 0.70 × 真实步骤分 + 0.30 × (1 − NASA/10)
```

老师的新需求是：**先预报下一个阶段的人因原始指标，再把预报结果送进上面这套 XGB 算 S**。模型不直接猜 S。

部署含义：任务做到一半（或刚做完上一阶段）时，用已经观察到的生理/眼动/操作，补全尚未发生的人因指标，再给出即将出现的负荷与绩效。

## 2. 「阶段」在这批数据里怎么定义

| 定义 | 样本规模 | 是否当作主方案 | 理由 |
|---|---|---|---|
| **A. 任务内时间切段** | 约 80 条（丢掉窗口过短的任务） | **是** | 一次任务就是一条连续过程；前半段 → 后半段就是「下一阶段」 |
| B. 同一被试的下一个任务 | 约 58 对 | 对照 | 每人 3 个**不同类型**任务，不是同一情景的下一幕 |
| C. 相邻 30s 窗（步长 5s） | 约 1.2 万窗 | 诊断 | 相邻窗重叠 25 秒，滞后-1 相关会被重叠抬高，不能当主证据 |

主方案 **A**：把一次任务的 30s/5s 窗口按时间顺序切成「已观察 / 未发生」。默认观察比例 **50%**；另外扫 25% / 33% / 67% / 75%，看「看到多少才能预报」。

每段至少 4 个窗口，否则该条不进入该比例的评测（仍可留在下游 XGB 的训练折里）。

## 3. 两段式，而不是端到端猜 S

```
已观察窗口
    → 预报模型（对照多种算法）
    → 补全后的任务级 264 维（与现有 XGB 输入同构）
    → 【冻结】27 维定额 XGB（只在训练被试的「真实 264 → NASA」上拟合）
    → 预测 NASA
    → 与真实步骤分合成 S
```

下游 XGB 的超参、定额、按被试五折，与正式口径 `exp_quota27_s.py` 一致。考试折**只替换 264 维输入**，不重训定额规则以外的东西。

对照用的上界 / 下界：

| 名称 | 送进 XGB 的 264 | 含义 |
|---|---|---|
| Oracle | 真实全任务 264 | 两段式在「指标预报完美」时的上限，应接近正式口径 NASA R² ≈ 0.55 |
| Early-only | 只用已观察段聚合出的 264 | 不做预报、把前半段当作整次任务 |
| Dummy / Persist | 训练集均值，或把前半段原样当成后半段 | 预报模型必须超过它们才算有用 |

## 4. 预报目标的几种数据处理

这些是**并列保存**的路径，不是互相覆盖。

| 版本 | 预报器看到什么 | 预报什么 | 如何还原全任务 264 |
|---|---|---|---|
| V1 `stage_late_pool` | 前段 264 | 后段 264 | 用两段的 n、mean、std 做矩合并；median/slope 为近似 |
| V2 `direct_full` | 前段 264 | **直接预报全任务 264** | 无需再拼（与下游 XGB 最对齐） |
| V3 `tile_late_mean` | 前段 264 | 后段 66 维均值 | 把均值铺到后段每一个窗，再与前段窗拼接后按原规则聚合（mean/std/median/slope 都定义完整） |
| V4 `horizon_windows` | 前段 264 + 最后一窗 66 + 时间位置 | 后段**每一个窗**的 66 维 | 拼接后按原规则聚合 |
| V5 `ar_rollout` | 当前窗 66 | 下一窗 66，滚动把后段填满 | 拼接后聚合。步长 1（重叠）与步长 6（约 30s 不重叠）分开记 |
| V6 `observe_ratio` | 同 V2 | 同 V2 | 观察比例网格 |
| V7 `next_task` | 本任务真实 264 | 该被试下一任务 264 | 直接作为下一任务的 XGB 输入 |
| V8 `quota27_space` | 前段里那 27 列 | 全任务那 27 列 | 其余列用前段填充。27 列每折在训练被试上现选 |

## 5. 预报算法

在适用的版本上跑同一组算法（小样本、多输出）：

- `dummy_mean`：训练折目标均值
- `persist_early`：前段 264 原样当后段 / 全任务
- `persist_lastwin_tile`：最后一窗重复铺满后段
- `ridge` / `ridge_scaled`：Ridge，α=10；后者先标准化
- `ridge_residual`（仅 V2）：预报「全任务 − 前段」残差再加回
- `pls6`：偏最小二乘，6 个潜变量（适合多输出、特征相关）
- `extra_trees`：浅 ExtraTrees（深度 4，200 棵，原生多输出）
- `knn5`
- `xgb_means`：只对 66 个 `__mean` 列做浅 XGB，其余统计量沿用 persist

曾试过 ElasticNet 多输出：264 个坐标下降在小样本上不收敛且极慢，已从主矩阵剔除，不作为有效路径。

## 6. 划分与泄漏

- **GroupKFold(n_splits=5)**，组 = 被试。同一人的所有任务、所有窗口不会同时出现在训练和考试。
- 中位数填充、互信息定额、预报器、下游 XGB：**只在训练被试上 fit**。
- 前段聚合只用 `windows[:cut]`，后段标签只用 `windows[cut:]`。
- EEG 的 `*_z_within_subject` 在预处理时是**按被试、跨该人全部窗口**算的，其中含有「本任务后半段 + 该人其他任务」。这与现有正式 XGB 输入一致，因此主实验沿用，才能把预报 264 送进同一套模型。真正的在线系统应改为「只用已经发生的窗口做 z 分数」。诊断报告会写明这条限制。

## 7. 指标

主指标（考试折预测拼回后一次性计算，即 pooled）：

1. **NASA R² / MAE** — 衡量人因预报是否真的有用
2. **S R² / MAE**（步骤 0.70 / NASA 0.30）— 与正式口径同一公式；S 会偏高，必须和 NASA 一起看
3. **指标预报 R²** — 264 列或 66 列按模态平均，看眼动 / 脑电 / 心率 / 行为谁能预报

不把「S R² 接近 0.98」当成预报成功：正式口径在**已经观测完整任务 264** 时才到 0.98，且 70% 来自真实步骤。
