# 趋势预测与预警：整套工作总览

本文把「趋势预测与预警」从问题、数据、算法、软件界面到发给软件公司的静态包写在一起。数字以仓库里的报告和 `reports/` 为准。

工作目录：`工作目录/03_建模/forecast_next_stage/`。

---

## 0. 一页结论

软件模块要同时做两件事：**左边画人因随时间怎么走，右边给出这场任务的预测绩效 S，并据此正常 / 预警。**

这两件事不能靠同一个头硬扛，所以做成双模块：

| 模块 | 界面 | 算法 | 本案例数字 |
|---|---|---|---|
| 轨迹 | 主图：左实线已观察，右虚线预测 | 窗级人因。橙色虚线 = Transformer 瞬时细节；蓝色点线 = Ridge 折出的整体走势 | 示范 `subject_02_task_5_6` |
| 绩效 / 预警 | 右侧人员状态，切换指标时**不变** | 已观察 27 维 → Ridge 补整场 27 维 → 冻结 XGB → 公式 S | 验证组 17 条 **S R² = 0.948，MAE = 0.025**；本案例预测 S = **0.679**，阈值 0.51 → **正常** |

S 一场任务只有一个数，不能画成随时间起伏的曲线。Transformer 虚线**不要**再积成 S。

---

## 1. 要解决什么

正式负荷口径（`s_score_from_nasa84`）是：整场任务做完，264 维人因 → 定额 27 维 → 浅树 XGB 得 NASA-TLX → 与真实步骤合成 S。那是「测完再算」。

趋势预测是：任务做到一半，新人只留下**本场已观察阶段**，要

1. 预报本场尚未发生阶段所对应的人因（给软件画「未来」）；
2. 给出这场任务的预测版 S（给预警）。

新人必须先有本场前半段记录，不能零观测只靠其他人的均值。模型**不直接以 S 为回归目标**。

---

## 2. 数据与切分

| 项 | 设置 |
|---|---|
| 被试 | 26 人 |
| 任务样本 | 84 条（可切半评测约 82 条） |
| 窗口 | 30 秒窗长、5 秒一步 |
| 每窗 | 66 个人因原料（脑电 / 心率 / 眼动 / 行为） |
| 任务级 | 66 ×（mean / std / median / slope）= **264 维** |
| 定额 | 折内互信息：眼动 6 + 脑电 5 + 心率 4 + 行为 12 = **27 维** |
| 已观察 / 未来 | 默认各 50% 窗口 |
| 划分 | 按被试 GroupKFold，5 折；同一人不会既训练又考试 |
| 验证组 | 被试 **2、7、12、16、23**，**17 条**任务 |
| 训练组 | 其余 21 人 |

绩效公式（步骤用真值，不预报）：

\[
S = 0.70 \times \text{真实步骤} + 0.30 \times (1 - \widehat{\mathrm{NASA}}/10)
\]

预警阈值（本演示）：**0.51**（低分位）。预测 S ≥ 0.51 为正常，否则预警。

---

## 3. 两层人因：不要画错对象

**窗级原料（能画成曲线）**  
每 5 秒一个点，例如 `hr_mean`（心率 bpm）、AOI 覆盖、操作密度。图上的黑 / 橙 / 蓝线都是这一层。

**27 维（不能画成曲线）**  
把一段窗口收成 27 个总结，例如 `hr_mean__slope`、`eye_aoi_coverage_ratio__median`。一场（或半场）各一个数。Ridge 预测的是「整场做完后这 27 个数」，不是每个时刻的 27 个数。

因此：

- 给老师讲「算法预测对象」：是这 27 个汇总，再进 XGB 得 S。
- 给软件画「随时间走的图」：只能画窗级原料；Ridge 在图上只能表现为一条**整体走势**（水平或缓斜），不能假装成第二条瞬时心率。

## 4. 正式预警路径（Ridge → S）

```
新人已观察窗口
    → 聚合成 264，取出本折定额 27 列
    → 标准化 Ridge（α = 10）：已观察 27 → 整场 27
    → 【冻结】浅树 XGB：27 → NASA（只在训练人的真实全任务 27 上拟合）
    → S = 0.70 × 真实步骤 + 0.30 × (1 − NASA/10)
```

Ridge 是带 L2 的线性映射，不是「取训练堆大平均」，也不是「把前半段 27 原样当整场」。对照：

| 做法 | 官方折大约 | 含义 |
|---|---|---|
| 抄前半段 27（persist_early） | S R² 0.908；NASA R² ~0.07 | 后半段等于没预测 |
| **Ridge 27** | **S R² 0.948 / 本复现折约 0.965**；NASA R² 约 0.65（该折） | 正式预警 |
| 全样本 82 条 Ridge | S R² 0.966；NASA R² 0.264 | 对外摘要以验证组 S 为准 |
| 真值 264（oracle） | S R² ~0.97；NASA R² ~0.53 | 上限对照 |

脚本：`run_matrix.py`，主路径 `v8_quota27_space` + `ridge_scaled`。  
明细：`reports/v8_quota27_space/models/ridge_scaled/predictions.csv`。  
正式 Word：`趋势预测_跨被试未来阶段人因与S_实验报告.docx`。

界面右侧**只写预测 S**，不写算法过程，不写真值 S。

## 5. 图上的预测（Transformer + Ridge 走势）

主图约定（已定稿，软件公司静态贴图即用）：

| 线 | 画法 | 含义 |
|---|---|---|
| 已观察 | 黑色实线 | 「现在」之前的窗级人因 |
| Transformer | 橙色虚线 | 「现在」之后的瞬时细节（池化 Transformer 直接预报，再按最后观测点锚定） |
| Ridge 整体 | 蓝色点线 | 有斜率列则用预报斜率从「现在」拉出去；否则画已观察均值水平线 |

实现要点：

- 编码器：最近 24 窗 → 16 维嵌入 → 单头自注意力 → 池化。
- 解码：正弦位置查询，输出后半段再插值。
- `direct` 保留波动；推理时 \(\hat y \leftarrow \hat y - \hat y_0 + y_{\mathrm{last}}\)，虚线从「现在」连上。
- 本机未走通 PyTorch 拉取，轨迹头用 numpy 自动微分复现，便于对照。

窗级 R² 仍是均值回归 / 残差更高，但虚线走平，不适合界面。**不以心率 R² 当正式成绩。**

## 6. 试过、但不采用的接法

| 版本 | 做法 | 结果 | 结论 |
|---|---|---|---|
| v10–v11 | 均值回归、Holt、KNN 等窗级基线 | 均值回归后半段 R² 约 +0.27 | 数好、线平 |
| v12 | LSTM / 小型 Transformer | LSTM R² 负；TF 约 +0.17 | LSTM 不用 |
| v13 | Transformer 多种接法 | resid 数较好；direct 更好看 | 界面后来改锚定 direct |
| v14 | 窗级预报拼回 264 再 XGB | 官方折 S R² 0.772，NASA **−0.489** | 假后半段污染 std/slope |
| v15 | 双头直接出 27 维 | S R² 0.884，但 NASA 常塌成同一个数 | 0.884 几乎是「真步骤 + 固定 NASA」 |
| v16 | 编解码器 + 差分 / 周期损失 | 仍塌成水平线 | 波动来自 pool_anchor，不是 EncDec |

v15 的 0.884 **不能**写成「Transformer 预测 S 也够用」：官方 17 条的预测 NASA 全是 5.925，没有负荷区分度。S 相关高，是因为公式里步骤已占 70%。

## 9. 不要写进对外结论的话

- 不说「Transformer 预测了 S」。
- 不把窗级心率 R² 或 NASA pooled 0.264 当主成绩。
- 不把虚线峰谷相位说成已经预报准了下一次波动。
- 不把虚线与阈值的交点写成已验证的超限时刻。
- 不把双头 S R² 0.884 当成可用的预警模型。
