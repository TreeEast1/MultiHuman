# MultiHuman：多模态生理-行为信号驱动的操纵员认知工作负荷预测

> 基于 EEG（脑电）、心率、眼动、任务操作日志四模态数据，预测核电操纵任务下操纵员的主观工作负荷（NASA-TLX 加权总分）。当前进度：**数据整理完成 + 特征提取方案确定 + 30秒/10秒双粒度特征数据集就绪**，尚未进入建模阶段。

---

## 1. 项目背景与目标

- **应用场景**：核电控制室操纵员（26 名被试）在 5 类核电操作任务（对应低/中/高三档难度）下的多模态生理与行为数据采集。
- **预测目标**：`NASA-TLX 加权总分`（任务级单一标签，1–10 分区间，本数据实际范围 1.333–7.800）。
- **早期方案已废弃**：项目历史上曾使用一个手工权重合成的"综合 S 指标"（`S = 0.4×任务表现 + 0.6×(1−NASA/10)`）作为目标，权重无依据、未做验证，已被推翻，改用纯 NASA-TLX 作为标签。历史阶段的所有脚本、模型与筛选特征封存在 `历史工作_存档_20260703/`（不入库），**当前工作与该目录零耦合**。
- **弱标签本质**：NASA-TLX 是任务结束后的一次性问卷评分，不存在逐秒真值。窗口级特征 → 任务级标签 是"多实例学习 / 弱监督"设定，评估时**必须按 `sample_id`（被试-任务）做 GroupKFold**，禁止窗口级随机划分（会导致同一被试同一任务的窗口既进训练集又进验证集，造成数据泄漏、指标虚高）。

## 4. 已完成的工作（当前进度）

### 4.1 数据整理

- 从历史多份混杂版本中，为每个模态挑出**覆盖范围最全、口径最新**的一份作为权威原始数据，重新按模态整理到 `data/`。
- 明确 26 被试、5 类任务、任务难度映射，确认 NASA/SART 各 82 条评分完整。
- 澄清了历史遗留的 S 指标错误（权重无依据），确定改用 NASA-TLX 加权总分作为唯一预测目标。

### 4.2 多模态时间对齐 + 切窗

见 `工作目录/01_预处理/scripts/`：

| 脚本 | 作用 |
|---|---|
| `step1_build_window_samples.py` | 从 `data/` 出发，按 `--window-sec` / `--step-sec` 切窗；对齐 EEG（Welch PSD 分频段功率）+ 心率（时域统计）+ 眼动（瞳孔/注视/AOI），产出每个"被试-任务"一个 CSV |
| `step2_add_log_features.py` | 解析操作日志文本，为每个窗口补充 32 个日志特征（`_win` 窗口内 + `_cum` 累计，两套并列） |
| `step3_blink_and_eeg_zscore.py` | 从眼动 `EyesNotFound` 段抽取眨眼代理特征（8 个），并对全部 28 个 EEG 特征做**被试内 z-score** |

已产出两份并行的窗口化特征数据集：

| 版本 | 窗口 / 步长 | 样本数 | 窗口数 | 特征列 | 用途 |
|---|---|---|---|---|---|
| `10秒窗口_不重叠版/加入日志特征/` | 10 s / step 10 s | 84 | 6 359 | 96 | 细粒度对比版 |
| `output_30s_step5s_final/` | 30 s / step 5 s | 84 | 12 624 | 132 | **当前主用** |

关键指标：NASA 标签 0 缺失；日志覆盖 100%（84/84）；同步质量 `good_eye_anchor` 69 / `check_large_duration_gap` 11 / `usable_hr_anchor` 4。

### 4.3 特征提取（附依据，非拍脑袋）

历史方案的 58 个特征清单**没有任何文献或统计依据**，已废弃。当前特征方案在 `工作目录/02_特征数据集/特征提取方案调研报告.md` 中逐项论证。要点：

**EEG（28 原始 + 28 被试内 z-score = 56 列）**
- 4 脑区（frontal / central / parietal / occipital）× 5 频段（δ/θ/α/β/γ）绝对功率 + 2 比值（θ/α, β/α）
- 频段边界沿用行业惯例；4 脑区全部保留但报告中明确 frontal + θ/α 比值为文献先验最强特征
- **修复历史遗漏**：对全部 28 个 EEG 特征做被试内 z-score，实测把 `frontal_alpha_power` 的个体间方差占比从 69.7% 压到 0.0%，个体差异完全剥离
- 未做的：绝对→相对功率转换（列在待办，需与用户确认是否要让 EEG 特征数翻倍）

**眼动（7 瞳孔/注视 + 9 AOI + 8 眨眼 = 24 列）**
- 补全历史缺失的**眨眼代理特征**：Tobii 无原生 blink 标签，用 `Eye movement type == EyesNotFound` 段作代理，**过滤 50 ms ≤ 段时长 ≤ 500 ms** 才算眨眼（<50 ms 多为追踪抖动，>500 ms 多为长时遮挡/离屏）
- 实测眨眼频率中位数 10 次/分钟、平均时长 85.5 ms，与文献自发眨眼 100–400 ms 下沿一致
- 眨眼归属规则：以中点所在窗口计入，避免跨窗重复计数

**心率（5 列）**
- `hr_mean / std / min / max / slope_bpm_per_min`
- **明确说明**：本数据是 4.6 s 采样一次的瞬时心率，非逐次 R-R 间期，**经典 HRV 指标（RMSSD/SDNN/LF/HF）在本数据上不可用**——历史方案没做 HRV 是数据格式决定的，不是遗漏

**日志（32 列 = 16 win + 16 cum）**
- `_win`：仅当前窗口内的操作次数、错误次数、重复次数、涉及设备数、动作类型分布等
- `_cum`：从任务开始到当前窗口结束的累计值
- 两套并存，通过后续消融实验决定取舍（未预先拍板）

**弱粒度权衡**
- 心率 4.6 s / 点 与操作日志（稀疏事件，30 s 窗口内约 66% 窗口为零动作）决定了窗口下限；5 s 窗口下心率与日志结构性失效，已放弃
- EEG 频率分辨率随窗口缩短显著恶化（Grimes et al. 2008：30 s→2 s 二分类准确率 92%→75%），10 s / 30 s 双版本并行以做粒度对比

### 4.4 遗留待决问题（未推进建模的原因）

见 `工作目录/02_特征数据集/特征提取方案调研报告.md` 第 6 节：
1. EEG 是否加相对功率（特征数会翻倍）
2. EEG 被试内 z-score 是否作为主特征（当前 step3 已加，与原始并列，等待建模消融）
3. AOI 指标定性：属"情境意识"而非"认知负荷"，报告口径确认
4. 日志 win/cum 是否都保留
5. 窗口粒度：以 30 s 为主还是 10 s 为主

## 5. 快速上手（复现特征提取）

前提：Python 3.9+，安装 `numpy pandas scipy openpyxl`。

```bash
# 假设完整原始数据已就位于 data/（含 04_EEG/ 与 05_眼动/）
cd 工作目录/01_预处理/scripts

# Step 1: 生成 30s / step 5s 窗口的 EEG+HR+Eye 特征
python3 step1_build_window_samples.py \
    --data-dir ../../../data \
    --output-dir ../output_30s_step5s \
    --window-sec 30 --step-sec 5

# Step 2: 补充 32 个日志特征
python3 step2_add_log_features.py \
    --data-dir ../../../data \
    --index-csv ../output_30s_step5s/index.csv \
    --sample-dir ../output_30s_step5s \
    --output-dir ../output_30s_step5s_with_log

# Step 3: 加眨眼 + EEG 被试内 z-score，得到最终数据集
python3 step3_blink_and_eeg_zscore.py \
    --input-dir ../output_30s_step5s_with_log \
    --eye-dir ../../../data/05_眼动/raw_tsv \
    --output-dir ../output_30s_step5s_final \
    --blink-min-ms 50 --blink-max-ms 500
```

10 秒窗口版把上面 `--window-sec 30 --step-sec 5` 换成 `--window-sec 10 --step-sec 10` 即可。

## 7. 关键工程规范

1. **数据源单一**：所有处理只从 `data/` 读取，不引用 `历史工作_存档_20260703/` 中的任何中间产物或特征结论。
2. **每步留三样**：脚本 + 输出 + README；任何特征筛选决策必须交代依据（文献 / 统计检验 / 物理意义）。
3. **窗口 / 预处理参数化**：便于跨粒度对比，禁止把窗口大小硬编码。
4. **评估协议**：任何模型评估必须 GroupKFold 按 `sample_id` 分组，禁止窗口级随机划分。
5. **弱标签如实标注**：不掩盖窗口预测本质是弱监督这一事实。
